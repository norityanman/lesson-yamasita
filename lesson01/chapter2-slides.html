2.1

しくみを知ると「どこが悪いか」当てられる

Claude Code に「ログイン機能を作って」と頼むと、4つ全部をまとめて作ってくれます。困るのはうまく動かないとき。カードを押して、どこが悪そうか考えてみましょう。

正解を当てることより「場所の候補を考える」ことが大事、と伝える。

3つ目は答えが1つに決まらない例。「分からないときは Claude Code に調べてもらえばいい」でOK。

2.2

骨組み（HTML）がないと内装はつけられないし、電気（JS）がなくても家には住めます。でも、スイッチを押して明かりがつくと便利ですよね。

「JavaScriptとJavaは別物」は聞かれたら答える程度でOK。

2.2

フレームワーク＝効率化の道具セット

つまずき注意
たとえ：パスタマシン

パスタは手打ちでも作れます。でも毎日たくさん作るならパスタマシンを使ったほうが速くてきれい。

Webも同じで、HTML/CSS/JSだけでも作れますが、大きなアプリはフレームワークという道具セットを使います。

「フレームワーク」という言葉で止まりやすい

難しく考えなくて大丈夫。「作業をラクにする道具」と言いかえてOKです。

覚えなくてOK

このコースでは Next.js（ネクスト・ジェイエス） を使います。

使いこなすのは Claude Code。みなさんは「画面を作るときの道具の名前」と知っていれば十分です。

読み方「ネクスト・ジェイエス」を一度声に出しておくと、後で Claude Code の画面に出てきたときに戸惑わない。

2.2

2.3

厨房（バックエンド）で起きていること

1シェフが注文を確認リクエストの中身を読む

たとえ

2.3

「ビジネスロジック」＝お店のレシピ

つまずき注意

言葉がかたくて身構えやすい

意味はシンプル。「そのアプリならではの計算やルール」のことです。

例：合計金額の計算／在庫があるかの確認／会員ならポイント2倍

たとえ

レシピ＝プログラム。「こんな注文が来たら、この手順で作って、こう出す」という手順書です。

例：ネットショップの会計

小計3,000円
＋ 送料500円
＋ 消費税（10%）350円
合計3,850円

この計算をしているのがバックエンドのレシピ

「ビジネスロジック＝そのお店のルール」と言い換えるのが一番伝わる。

税は（3,000＋500）×10%＝350円。送料にも消費税がかかる点は聞かれたら補足。

2.3

バックエンドの代表的な仕事

ログインIDとパスワードを照らし合わせて、本人か確かめる
データの保存投稿・購入・登録をデータベースに書き込む
計算・変換「小計＋送料＋税＝合計」などを出す
外部サービス連携決済（Stripe）・メール送信・他社のAPIを呼ぶ
覚えなくてOK

Python（パイソン）＝読み書きしやすいプログラミング言語
FastAPI（ファスト・エーピーアイ）＝Pythonで裏側を速く作る道具

あなたの立場

みなさんはレストランのオーナー。

レシピを書くのはシェフ（Claude Code）。オーナーは「こんな料理を出したい」と伝える係です。

「オーナー」の立場を強調すると、非エンジニアの受講者が自分の役割をイメージしやすい。

Stripe＝ネット決済のサービス。名前だけでOK。

2.3

場所が分かると、頼み方が変わる

こんな症状あやしい場所Claude Code への頼み方
画面は出るのに、データが保存されないバック か DB「バックエンドのデータ保存処理を確認して」
ログインできないバックの認証処理「ログインAPIのパスワード照合の処理を確認して」
しくみを知らないと「うまく動きません」
しくみを知っていると「画面は出るけど、保存のところで止まっているみたい。バックエンドを見て」

完璧に当てなくてOK。「たぶんここ」と添えるだけでClaude Codeの調査が速くなる、と伝える。

2.4

あなたが伝えるのは「どんなデータを扱うか」

テーブルの設計は Claude Code がやってくれます。でも何を記録したいかは、お店のオーナーにしか分かりません。

指示の例「ユーザーは名前とメールで登録できるようにして。商品には名前・価格・説明文・画像を持たせて。ユーザーが商品を購入した記録も残して。」

3つの言葉を使えると強い

テーブル＝表、項目（カラム）＝列、リレーション＝番号でのつながり

覚えなくてOK

このコースでは PostgreSQL（ポストグレス・キューエル）を使います。無料で広く使われているデータベースの名前です。

PostgreSQLは「ポスグレ」と略されることも多い、と一言添える。
